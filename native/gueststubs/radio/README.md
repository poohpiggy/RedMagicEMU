# Isolated Android 16 Radio voice prototype

This is an unregistered, single-slot prototype. It is not launched by RedMagicEMU and does not register a HAL or connect to the host. It does not make real calls. The SMS service, private host bridge, other radio interfaces, initialization, and end-to-end acceptance are separate unfinished work.

`aidl/base` and `aidl/voice` contain the required compile-time subset of the Android Open Source Project frozen AIDL v4 snapshots from `platform/hardware/interfaces`, tag `android-16.0.0_r1`, paths `radio/aidl/aidl_api/android.hardware.radio/4` and `radio/aidl/aidl_api/android.hardware.radio.voice/4`. Their original copyright notices and the Apache License 2.0 are preserved in the files and `aidl/LICENSE-2.0.txt`. The `.hash` files are the official hashes of the complete frozen interfaces, not checksums of this subset. These sources are pinned; building must not automatically fetch or update upstream.

The AIDL-generated `android.*` classes and `compile-only/android/os` signatures are **compile-time inputs only**. They must never be included in the Guest DEX: at runtime the service uses the target Guest boot classpath. `RadioVoiceContractTest` checks the target signatures and callback semantics locally; `RadioVoiceBinderContractTest` uses a synthetic bootstrap Binder to test cross-process transport without declaring or registering `slot1`.

For an offline, isolated build and host contract tests of voice, messaging, config, modem, SIM, network and data, run `python native/gueststubs/radio/verify_offline.py --sdk <local-android-sdk>`. This requires a local JDK, Android API 36 platform and build-tools 36.0.0; `--java-home` and `--build-tools` can select local alternatives. All build files are temporary unless `--output <new-jar-path>` is supplied. The output jar contains tests and is never a production service artifact. The script checks that its DEX contains only `app.aemu.stub` classes, and compiles but does not execute the Guest-only cross-process Binder tests. A successful host run does not prove Guest service initialization, SMS or call delivery.

Before generating interfaces, the script checks the exact file set and individual SHA-256 values of the frozen AIDL subset and its `.hash` files against `aidl-sha256.json`. The AOSP `.hash` files identify the complete frozen interfaces; the SHA-256 manifest checks the locally included subset. Run `python native/gueststubs/radio/tests/test_verify_offline.py` for the snapshot-tampering and selected-JDK environment regressions.

The seven unregistered service prototypes have an optional `RadioRequestCounter` for isolated initialization experiments. It is disabled by default and counts only bounded transaction numbers; it does not inspect Parcel data, serials, identities, or response contents. A snapshot must be mapped to names using the pinned interface transaction table. The counter stops after its configured limit and sets `truncated` when another event is observed; reaching the limit without that flag is not evidence that no later request occurred. It observes entry to `onTransact`, not whether a callback succeeded or the framework completed initialization. Enabling it can change timing. The Guest-only `RadioTraceBinderTest` compares disabled/enabled voice transactions, callbacks, and version/hash through a synthetic remote Binder; it is not a test of the other six services or a real `slot1` registration.

`RadioSyntheticRegistry` and `RadioSyntheticProcessTest` are isolated experiments and are not connected to production startup. The registry only accepts a 32-digit lowercase hexadecimal token and publishes seven synthetic names; all seven stub objects share one synthetic state. It bounds registration and readiness checks, but cannot undo a partial Binder registration: the experiment process must exit after any failure, timeout, or close. A blocked registration might complete after its caller times out, so closing the Java object alone is not cleanup. The precheck and add are not atomic. The JVM contract tests exercise synthetic success, collision, partial failure, unready, and timeout; they do not demonstrate real registration.

On the test Guest, publishing the first actual VINTF-stable Radio stub under a synthetic name failed with `IllegalArgumentException: VINTF declaration error.` No synthetic service remained in 21 subsequent name checks, and the test processes exited. Thus real registration, cross-process readiness of all seven services, framework initialization, and inbound delivery remain unverified; neither a formal Radio name nor a VINTF modification was attempted. Any future declaration experiment needs independently verified instance ownership, lifecycle, rollback and real loader behavior first.

`RadioCanaryRegistration` and the Guest-only `RadioVintfCanaryTest` implement a smaller, single-service experiment; they do not create a VINTF fragment or run during VM startup. The only permitted service name is `android.hardware.radio.config.IRadioConfig/rme` followed by a 32-character lowercase hexadecimal token. The host contract checks undeclared and occupied names, injected add failure, readiness timeout, blocked add, invalid names, and process-exit requirement after failure or close. The Guest entry point checks declaration, starts the real config stub with a synthetic state, verifies descriptor/version/hash from a different process, and checks absence after server exit. It exits on any failure; stopping or timing out a Java worker alone cannot retract Binder registration, and name precheck/publication are not atomic.

One manually controlled clone Guest experiment published a single synthetic config declaration, observed `isDeclared=true` with a different token false, and exercised the real config Binder from another Guest process. Its descriptor/version/hash matched and its name was absent after the server process exited. After normal shutdown, the temporary declaration was removed following file identity and content verification; a subsequent Guest boot reported the same token undeclared and was shut down normally. The readiness check observes a same-name Binder with the expected descriptor, not Binder identity under a racing publisher. This experiment does not establish crash-safe recovery, automatic exclusion of other writers, phone-framework initialization, inbound delivery, or complete Radio HAL compatibility; it is not connected to production startup.

This prototype is not ready for service registration. Timeout, close, callback-rebinding, and callback-generation tests exercise synthetic callbacks; concurrent death, shutdown, and in-flight events still require broader cross-process verification. Unsupported requests bypass the state-event queue but hold their callback generation until their reply returns. Binder linking, unlinking, and callbacks can block in local implementations: a timed-out close reports failure and cannot force a blocked thread to stop. Deferred detach failures are retained by `getAsynchronousCleanupFailure()`; any future integration must monitor and surface that diagnostic. No private host event channel has been connected or verified for production use.
