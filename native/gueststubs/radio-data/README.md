# Isolated Android 16 Radio data prototype

The default `slot1` service creates no cellular data bearer and does not access host networking or SIM information. An explicitly configured synthetic radio that is ON reports an empty data-call list; an OFF or disconnected radio reports `RADIO_NOT_AVAILABLE`. Data-call setup and the other unimplemented operations respond with `REQUEST_NOT_SUPPORTED` and the original serial.

The target launcher may opt in with `--lte-data`. In that mode, `setupDataCall` returns one synthetic active IPv4 bearer on the existing host-backed `eth0` route (`10.0.2.15/24`, gateway `10.0.2.2`, DNS `8.8.8.8` and `1.1.1.1`). The Guest telephony framework, not this service, creates the `CELLULAR` NetworkAgent. Data disallow, radio OFF or disconnect, callback death, service close, and deactivation remove the call and close `/dev/aemu_network_gate`. The bearer uses the existing host network channel; it never connects to the host cellular stack. Device-level APN selection, default-network validation, mobile-data UI behavior and switching from Ethernet/Wi-Fi remain unverified until tested on the target Guest.

`aidl/data` contains the frozen Android Open Source Project Radio data AIDL v4 snapshot from `platform/hardware/interfaces`, tag `android-16.0.0_r1`, path `radio/aidl/aidl_api/android.hardware.radio.data/4`. The original notices remain in the source files; the Apache License 2.0 copy is in `../radio/aidl/LICENSE-2.0.txt`. The `.hash` is the official interface hash, not a checksum of this directory. Builds never fetch or update upstream.

Run `python native/gueststubs/radio/verify_offline.py --sdk <local-android-sdk>` for the isolated host contract tests and test DEX. `RadioDataNoBearerTest` preserves the default unsupported behavior; `RadioDataLteTest` covers the opt-in call, link properties, gate and teardown. Generated `android.*` interfaces are compile-only and are not packaged. Real Binder serialization, process death/rebind races, lifecycle safety, and Guest framework interaction require target-device validation.
