# Isolated radio event gate prototype

The production Radio service group now holds a dormant `RadioEventEndpoint` connected to its own messaging and voice objects; it does not start a session, register an event service, create a listener, or access host telephony. The native event gate and transport remain isolated prototypes, not connected to production. They validate bounded, synthetic event frames received on an already-connected Unix `SOCK_SEQPACKET` socket with `SO_PASSCRED`; the gate requires the host connection credentials and per-message credentials to match the expected physical PID and UID. The supplied pidfd must come from an authenticated launcher for that same physical process. A missing or mismatched pidfd, closed process, truncated control or data, unexpected ancillary data, invalid epoch, malformed length, and repeated or non-consecutive sequence are rejected. Received `SCM_RIGHTS` descriptors are closed before rejection.

`RME1` contains a big-endian 64-bit epoch, big-endian 64-bit sequence, one-byte event kind, big-endian 16-bit payload length, and 1–256 payload bytes. In the isolated Java model, kind 1 carries a synthetic SMS PDU, kind 2 an incoming number, and kind 3 is an acknowledgment. Kind 4 requests host-side hangup: its payload is exactly 16 bytes, the big-endian epoch and sequence of the incoming kind 2 event. Both identifiers are nonzero and the referenced epoch must equal the current session. The voice model compares both fields against the current call, not against its number or Android call index. Malformed or replayed frames do not advance the sequence; a well-formed request that names a different call is rejected after consuming its own sequence.

Each gate must have exactly one serialized receiver; it is not thread-safe. Validation advances the sequence before any consumer processes the event. A submitted acknowledgment describes only the local operation, not that the framework or user received it; an uncertain result must not be automatically retried as though nothing happened.

The isolated managed path assigns nonzero, non-wrapping epochs from a counter shared by managers in the same class loader and admits one manager per voice instance. This does not guarantee uniqueness across class loaders or process restarts, and there is not yet a host handshake or persistence mechanism. A manager permits a replacement session only after the prior session's queued, matching-epoch cleanup succeeds. Busy, timed-out or failed cleanup returns `UNCERTAIN` and marks the manager as requiring process exit; that flag does not itself terminate a process. Concurrent duplicate close can return `IN_PROGRESS`, which is not a completed cleanup. The legacy constructors and source flags are internal test mechanisms, not authentication capabilities.

`RadioEventSessionPump` is an isolated framed-transport adapter: EOF and transport errors trigger session cleanup, and it retains ordinary transport and cleanup failures separately. Its transport must already be authenticated; the pump has no real socket implementation, does not own or interrupt a blocking read, and a caller must handle `IN_PROGRESS` or `UNCERTAIN`. This is not a durable queue or transaction, and production integration must handle an authorized process dying after the final liveness check; a pidfd and message credentials do not defend against compromise of the authorized process itself.

`tests/gate_test.c` checks fail-closed parsing with synthetic credentials. `tests/recv_test.c` exercises a real Unix socketpair and pidfd with malformed packets, same-UID child injection, and received-descriptor cleanup. `tests/launcher_harness.c` and `tests/launcher_guest.c` are an isolated launcher-to-N64 Guest experiment; they require explicitly supplied existing launcher and engine paths and an empty temporary root. They must not be pointed at the user's firmware root, register `slot1`, or create a network listener.

`RadioGuestPeerCredentials` only validates already-received metadata; it neither authenticates a connection nor receives packets or closes descriptors. `diagnostics/guest_credentials_probe.c` and `diagnostics/RadioGuestCredentialsProbe.java` are a separate synthetic Unix-socket experiment, not a production channel. In one existing-clone N64 run, the Java side accepted the parent sender's kernel credentials and rejected a same-UID fork's credentials against the parent's PID. Both sender and receiver were Guest processes under N64, not the actual host UI process. The experiment did not test ancillary FD cleanup, credential truncation, lifecycle or actual SMS delivery.
