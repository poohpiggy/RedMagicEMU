# EMU Vulkan client pipe

`emu_pipe.c` provides the gfxstream QEMU-pipe client functions over the Guest
Unix socket `/dev/socket/aemuvk`. The socket path is translated by the normal
Guest runtime. Each connection selects the upstream `opengles` or
`GLProcessPipe` service using its NUL-terminated `pipe:` prefix; remaining bytes
are passed unchanged. These are blocking streams; other services, namespaces,
and nonblocking flags are not supported. A host service must implement the
corresponding protocol and isolation before this client can be used.

Run `python3 native/vulkanbridge/client/test_emu_pipe.py` on Linux to check both
selectors, byte transfers, absent service and EOF. This uses a local test peer,
not the renderer. The source also cross-compiles to Android ARM64 with the NDK.
The client is not packaged or connected to a Guest. This test establishes neither
Vulkan synchronization nor GPU rendering.

For a local integration with the same-revision AndroidPipe process service,
run `test_pipe_integration.sh` with the gfxstream build root and the patched
AndroidPipe object generated by the channel experiment's `verify.sh`. This
exercises the actual EMU client, socket server and upstream process service;
it obtains a real process-pipe ID, checks disconnect cleanup, and checks that
the graphics connection closes when no renderer exists. Its same-PID
authorization callback is solely for this in-process test. The renderer is not
initialized, and a product authorization policy remains to be implemented.

## Guest device enumeration probe

`guest_device_probe.cpp` opens the existing process and graphics pipes, then
uses the gfxstream encoder to create an instance, enumerate a physical device,
query its properties and destroy the instance. The host launcher accepts
`--guest-probe GUEST_ROOT N64_RUNNER GUEST_PROGRAM GUEST_LIBDIR` after its
parent PID and display arguments. It launches the sole authorized Guest
process, serves the socket, drains the render workers and removes the socket.

Build the client from the linked local encoder candidate:

```sh
REPO=/mnt/e/RedMagicEMU
OUT=$(mktemp -d "$REPO/build/diagnostics/rme-guest-encoder.XXXXXXXX")
python3 "$REPO/native/vulkanbridge/client/build_guest_device_probe.py" \
  /var/tmp/rme-encoder-native-validation-v1/android1-VkEncoder.command.txt \
  /var/tmp/rme-client-link-verify-6gqo43d8/libvulkan-client.so \
  /var/tmp/rme-vk-client-gles \
  /var/tmp/rme-mesa-android-6ekppv9b/build12/subprojects/libdrm-2.4.133/libdrm.so \
  "$OUT/build"
```

Build the host bundle with the command in the
[AndroidPipe startup README](../../../tools/diagnostics/gfxstream-androidpipe-channel/README.md#android-debug-renderer-startup).
Stage its files in private app cache and the client files in a unique Guest
`/data/local/tmp` subdirectory. The launcher passes the Guest directory via
the N64 runner's existing per-process `AEMU64_LIBPATH`. Run the host launcher
as the debug app UID with its private library directory in `LD_LIBRARY_PATH`.
Add `--compute` as the final launcher argument to run two Vulkan compute
pipelines on the same connection. The probe uploads 64 input values with
`vkCmdUpdateBuffer`. The first shader writes indirect dispatch sizes into a
storage buffer. The second shader is dispatched from those sizes and the
Guest reads the pipeline statistics using `vkGetQueryPoolResults`. Two
direct dispatches calibrate the counter. Every output is compared against
`3 * input + 7`. The counter reflects the device's implementation. See
[Vulkan pipeline statistics](https://docs.vulkan.org/refpages/latest/refpages/source/VkQueryPipelineStatisticFlagBits.html).

Use `--expect-mismatch` to change the expected first value by one. A valid
negative run reaches `GUEST_VULKAN_COMPUTE_MISMATCH index=0`, reports exactly
one mismatch and exits 1. Remove the temporary staging directories after the
run. The compute probe covers query-based readback. Ordinary Guest app
loading, mapped buffer readback and OpenCL require separate tests.

Use `--readback` to read the actual storage-buffer bytes. The probe selects
host-visible memory, waits for the compute fence and uses the existing
gfxstream `vkInvalidateMappedMemoryRanges` copy reply. It encodes one
explicit 768-byte range at offset zero with the generated gfxstream
marshaller. The Guest verifies all 64 transformed integers and the remaining
128 words. `--readback-expect-mismatch` must report exactly one mismatched
result and exit 1. This uses the paired renderer's copy mode and a
probe-owned output array. Standard `vkMapMemory` semantics for applications
and OpenCL still need integration.

## Public Vulkan ABI and mapped buffers

Build the public client and stream objects with `--emu-vulkan-pipe` in
`compile_android_device.sh` and `compile_stream_components.py`. Rebuild the
encoder with `rebuild_encoder_candidates.py`, then run
`patch_shared_memory_client.py ENCODER_OUTPUT MAPPED_ENCODER_OUTPUT`. Link the
two rebuilt objects and the other objects from the encoder output with
`strict_link_android.sh`. Use the Android Mesa archives built with
`HAVE_LINUX_FUTEX_H`.

Build the paired renderer with `build_renderer_service.py --shared-memory`.
Set `RME_VULKAN_SHARED_MEMORY=cached` for the Geekbench compute test. The
Guest maps CPU-cached shared pages. Flush and invalidate calls synchronize
those pages with native Vulkan allocations, using the Adreno buffer's own
memory requirements. Set `RME_VULKAN_SHARED_MEMORY=1` to exercise the separate
Adreno path that allocates Android BLOBs and imports them into Vulkan. In this
mode, buffers created with the internal BLOB handle type report only the
compatible mapped memory type. Normal images and other buffers exclude that
type.
Build `guest_public_vulkan_probe.c` with `-DRME_TEST_MAPPED_MEMORY` and
`-DRME_TEST_INSTANCE_EXTENSIONS` to check Vulkan extension enumeration and
read/write mapping. Run it with `--guest-probe` and pass the path of the public
client as the final argument. Add `-DRME_TEST_CACHED_MEMORY` for the cached
mode. The probe then copies through a device-local buffer and checks both
mapped buffers after a GPU fence. Use `-DRME_TEST_COHERENT_DEVICE_LOCAL`
instead of `-DRME_TEST_CACHED_MEMORY` to exercise the same transfer without
explicit flush or invalidate calls and compare the two buffer requirement APIs.

Set `RME_VULKAN_SCOPED_DMA_SYNC=1` when running `patch_shared_memory_client.py`
to enable scoped DMA-BUF transitions. A batch of legacy transfer commands
without semaphore dependencies ends CPU access only for its bound memory.
Draws, dispatches, secondary command buffers, unresolved bindings and
semaphore dependencies use full synchronization. Fence and queue completion
preserve the existing CPU-access transitions.

`stage_guest_vulkan_runtime.py ADB SERIAL GUEST_ROOT BUNDLE` temporarily stages
the public client from `libRmePublicVulkan.so` and its client-only dependencies in
a stopped Guest runtime. Use the same command with `--restore` to reinstate the
original loader from its byte-checked backup. The bundle names match the
standalone public probe. The runtime uses its own system `libdrm.so`.

The debug renderer can listen before an app starts with
`--guest-app GUEST_ROOT wait`. After `RME_VK_GUEST_APP_READY`, supply the
verified native Guest app PID as a decimal line on stdin. The listener admits
only that live PID and the EMU UID. Send `Q` on stdin to release the session.
The physical Adreno BLOB layout and mapped buffer data path were checked on the
test phone. Full synchronization on this path scales with the total mapped
allocations. Other layouts and workloads need separate verification.

## Normal APK with the GPU bridge

Build the paired renderer with `build_renderer_service.py --shared-memory`
and the Guest client as described above. Use the Android ARM64 clvk build
with the online clspv compiler. The pinned versions are recorded in
[the clvk build notes](../../../tools/diagnostics/clvk-local-memory-report/README.md#较新上游的隔离复验).
Run `build_clvk_guest.py NINJA ANDROID_CLVK_BUILD OUTPUT_DIR` on that build.
The relink uses the actual 8-bit and 16-bit storage and shader feature
bits for core Vulkan versions that have promoted those extensions. It
copies a `CL_MEM_USE_HOST_PTR` mapping back only when it was mapped for
writing.
Stage those three outputs and their upstream notices with
`package_gpu_bridge.py RENDERER_OUTPUT GUEST_BUNDLE LIBOPENCL BUILD_OUTPUT --notice NAME FILE ...`.
Use `build/generated/rme-gpu-bridge` as `BUILD_OUTPUT`. The normal
`:app:assembleRelease` and `:app:assembleDebug` tasks include that stage.
On a clean checkout, both tasks use the [paired GPU bundle](../../gpu-runtime/README.md).

Start a GPU-enabled NX809J/API 36/ARM64 instance through the APK. The VM
starts its own renderer, waits for the socket, and installs the verified
Guest library assets before starting Android. Each admitted N64 process
is pinned and has a separate process pipe and resource identity. OpenCL
compiles kernels with clspv in the Guest and uses the same Vulkan
connection to run them on the host GPU.

The package saves the original public libraries and linker declarations
under the instance's `run/gpu-runtime-original` directory. Booting the
instance with GPU disabled restores them, as does booting with an APK
that uses this runtime integration but omits the staged bridge.
Before installing an older APK without the runtime integration, boot the
instance once with GPU disabled to restore the original files.

For the native OpenCL APK, stage the same Vulkan payloads with the paired
OpenCL client and host described in [the native OpenCL build](../../openclbridge/README.md#regular-android-apk).
